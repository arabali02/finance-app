# Финансовый сайт для KEMEL и JARYQ: дизайн

## Зачем
Владелец двух магазинов (KEMEL — мужская одежда, JARYQ — кроссовки) хочет видеть **реальную чистую прибыль** каждого магазина и общую, контролировать расходы до мелочей, вести личный бюджет отдельно от бизнеса и копить на цели (например, отдельное здание).

## Цели
- Быстрый ручной ввод операций с телефона и компьютера (2–3 нажатия).
- Чистая прибыль по магазину и общая за день / неделю / месяц / произвольный период.
- Расходы по категориям, сравнение KEMEL vs JARYQ.
- Налог по упрощёнке считается автоматически (ставка по умолчанию 2%, настраивается).
- Личный бюджет — отдельный раздел, не смешивается с бизнесом.
- Цели накоплений с прогрессом.
- Выгрузка отчётов в Excel.

## Не цели (первая версия)
- Склад с остатками по товарам и размерам.
- Импорт выписок, интеграция с Kaspi или банком.
- Уведомления в Telegram, план/факт, прогнозы.
- Несколько пользователей и роли; казахский язык; свой домен.

## Анти-цели (провал, даже если работает)
- Прибыль считается неверно (например, закупка товара учтена дважды: и как расход, и как себестоимость).
- Ввод операции занимает больше 15 секунд — тогда учёт забросят.
- Данные могут потеряться или быть видны посторонним.

## Ограничения
- Бюджет 0 ₸: бесплатные тарифы Supabase и Vercel.
- Один пользователь (владелец), вход по email и паролю.
- Валюта — тенге, язык — русский.
- Одинаково удобно на телефоне и компьютере.

## Подходы
| Подход | Плюсы | Минусы |
|---|---|---|
| **А. Next.js + Supabase (Postgres + Auth), хостинг Vercel** ✅ выбран | Синхронизация между устройствами, надёжное хранение, вход по паролю, бесплатно | Разовая регистрация в Supabase и Vercel |
| Б. Только браузер (localStorage) | Ноль настроек | Нет синхронизации, данные легко потерять |
| В. Google Sheets как база | Привычная таблица | Медленно, хрупко, лимиты API |

Пользователь выбрал **А**.

## Модель денег (как считается прибыль)
- **Выручка**: продажи по магазину и способу оплаты (Kaspi, наличные, терминал).
- **Себестоимость проданного (COGS)**: закупочная стоимость проданного товара (вписывается в итог дня).
- **Операционные расходы**: аренда и коммуналка, зарплата, реклама, доставка товара и прочее; у каждого расхода выбран магазин или «общий» (общие делятся между магазинами пополам — *наше решение*, можно изменить).
- **Налог** = выручка × ставка (2%).
- **Чистая прибыль** = выручка − себестоимость − операционные расходы − налог.
- **Закупка товара** — это движение денег, а не расход в прибыли: показывается в разделе «Деньги» (сколько ушло на товар), но в чистую прибыль не попадает, чтобы не считать её дважды.
- **Вывод в личное**: перевод из бизнеса в личный бюджет уменьшает деньги бизнеса, но не прибыль, и появляется доходом в личном разделе.

## Экраны
1. **Главная**: прибыль за сегодня и месяц (общая + по магазинам), кнопка «+».
2. **Быстрый ввод**: тип (итог дня / расход / закупка / вывод в личное) → магазин → суммы (для итога дня: Kaspi, наличные, терминал, закуп проданного) или сумма и категория → сохранить.
3. **Операции**: список с фильтрами, редактирование и удаление.
4. **Отчёты**: период; прибыль; расходы по категориям (диаграмма); KEMEL vs JARYQ; кнопка «Excel».
5. **Личный бюджет**: доходы и расходы по личным категориям, остаток месяца.
6. **Цели**: сумма, накоплено, прогресс-бар, ручное пополнение.
7. **Настройки**: ставка налога, категории, магазины.

## Технические решения (наши)
- Next.js (App Router) + TypeScript + Tailwind; Supabase Postgres с Row Level Security по user_id; Supabase Auth (email и пароль).
- Деньги хранятся целыми тенге (integer), без дробей.
- Excel-выгрузка на клиенте через SheetJS.
- Графики — Recharts.
- Расчёт прибыли — чистые функции с unit-тестами (Vitest).

## Оставлено исполнителю
Структура папок, точная схема таблиц, вид компонентов — в рамках этого документа.

## Решения владельца по вводу
- Продажи вносятся **итогом дня**: одна запись на магазин и день, суммы по Kaspi, наличным и терминалу.
- В той же записи владелец вписывает **сумму закупа проданного товара** (себестоимость дня) — из неё считается прибыль.
